One weight,
two minds.

同一份 Qwen3 權重,兩種推理模式並排 — Fast 直答、Think 顯式推理。 左右兩邊背後是同一個模型,只有 chat template 不同。看 thinking 模式怎麼用 token 與延遲換深度。

§ 01 Specimen
Input · Mode

Pick a question, pick a mode.

四個範例問題從算術到程式由簡入繁。Fast 是 enable_thinking=False,直接吐答案; Think 是 enable_thinking=True,先輸出 <think> 區塊再回答。 切換不會更改權重 — 只是換一個 prompt template。

§ 02 Comparison
Fast · Think

Same weights, different shape.

左欄 Fast 用鼠尾草綠 — 短、平、即時。右欄 Think 用石板藍 — 把 chain-of-thought 顯性吐出來,可審計、可中斷。 兩邊的「答案」段往往幾乎一樣 — 差別在前面那段思考被不被吐出來。

§ 03 Cost
Tokens · Latency · Ratio

Depth has a price.

Think 模式幾乎一定吐更多 token、花更多毫秒。問題不是「該不該用」,而是「值不值得」 — 簡單算術下 Think 是純成本浪費;複雜推理下 Think 把正確率拉上去,1.5–4× 的成本是合理對價。

§ 04 Reading
When to flip

When to flip the switch.

雙模式統一的設計把「該不該深思」變成 prompt-time decision — 同一個模型,呼叫端決定。 多數 production 流程的最佳實踐:預設 Fast,在偵測到難題時才升級到 Think,bullet 點如下。

Fast mode · default
事實查詢、固定格式輸出、結構化 extraction、互動式聊天、首屏即時回應。延遲是體驗,Think 反而扣分。
Think mode · upgrade
多步推理、數學/邏輯題、程式 debug、需要審計的決策、不確定時自我檢查。慢一點換不會錯。
Budget = 0
等同 Fast — 用同一個 Think endpoint 處理混合流量,只在需要時把預算開上去,不必雙路由。
Hybrid router
用第一個小模型判題難度 → 決定 budget。簡單題 0、中等題 256、難題 2048 — 平均成本降一半。
