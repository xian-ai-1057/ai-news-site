# MIT 提出 TLT：用「閒置 GPU」訓練動態草稿模型，推理模型訓練速度翻倍

> [!info] 文章資訊
> - **來源**：[MIT News](https://news.mit.edu/2026/new-method-could-increase-llm-training-efficiency-0226)
> - **發布日期**：2026-02-26
> - **分類**：技術理論

## 📝 重點摘要

MIT、NVIDIA、ETH Zurich、MIT-IBM Watson AI Lab 與 UMass Amherst 的聯合團隊提出名為 **TLT（Taming the Long Tail）** 的訓練加速系統，專門針對推理型 LLM 的強化學習（RL）訓練流程。研究團隊發現 RL 訓練中最耗時的環節是「rollout（生成多個候選答案）」，可佔總訓練時間的 85%，且其中存在大量 GPU 閒置時間。TLT 自動利用這些閒置時段訓練一個小型「draft 模型」進行推測解碼（speculative decoding），並動態保持其與目標模型對齊。在多個推理 LLM 上實測，TLT 將訓練速度提升 **70% 至 210%**，同時保持模型精度不變。論文將發表於 ACM ASPLOS。

## 📖 全文內容

### 問題背景：推理模型訓練的計算瓶頸

推理型 LLM（reasoning LLM）的設計目標是把複雜問題拆解成多步驟解決，特別擅長進階程式設計、多步規劃這類「會被一般 LLM 卡住」的任務。但訓練這類模型耗費大量算力與能源——核心原因是「強化學習 rollout」階段的低效率。

RL 訓練的流程是：
1. 模型針對一個 query 產生多個候選答案
2. 系統挑出最佳答案並給予獎勵
3. 根據最佳答案更新模型

「實際上『更新模型』那一步耗時非常少。」共同第一作者、MIT 博士後 Qinghao Hu 指出，「真正的瓶頸是 rollout——生成多個候選答案這件事可以佔到 RL 訓練總執行時間的 85%。」

更糟的是，rollout 階段所有 GPU 必須等到「全組都完成最長那條回應」才能進入下一步。這意味著生成短答案的 GPU 必須空轉，等其他 GPU 跑完長答案。

### 既有技術為什麼不夠用：推測解碼的靜態限制

研究團隊原本想直接套用「推測解碼（speculative decoding）」。推測解碼會訓練一個輕量級的小模型（drafter）來快速猜測大模型的未來輸出；大模型一次性驗證所有猜測，被接受的就直接拿來用，從而把序列式生成變成並行驗證，大幅加速。

但傳統推測解碼有個根本問題：drafter 只訓練一次後就固定不動。**這在 RL 訓練中行不通**——推理模型在 RL 訓練過程中會被更新數千次，drafter 跑幾步就會「過時」變得無用。

### TLT 的兩個核心元件

研究團隊設計了一個自適應系統「Taming the Long Tail（TLT）」，包含兩個關鍵元件：

**1. 自適應 Drafter 訓練器（Adaptive Drafter Trainer）**

利用 RL rollout 階段的 GPU 閒置時間，**即時訓練 drafter 模型**，讓它持續與目標推理模型對齊。Hu 解釋：「只要某些 GPU 完成了短 query 進入閒置，我們立即把它們切換去訓練 drafter，使用的還是同一批 rollout 資料。」這個機制的關鍵在於「不增加額外計算成本」——閒置算力本來就會被浪費，TLT 把它重新導向有意義的用途。

**2. 自適應 Rollout 引擎（Adaptive Rollout Engine）**

管理推測解碼的執行邏輯，**根據每一批輸入的特性自動選擇最佳策略**。它會即時觀察 drafter 模型處理的輸入數、目標模型在驗證階段接受的輸入數等指標，動態調整推測解碼的配置。

此外，drafter 模型被刻意設計得很輕量，且 TLT 重複利用推理模型訓練流程中的部分元件來訓練 drafter，進一步壓低訓練負擔。

### 實驗結果

在多個基於真實世界資料集訓練的推理 LLM 上實測：

| 指標 | 結果 |
|---|---|
| 訓練速度提升 | 70% 至 210% |
| 精度 | 完全保持，無任何下降 |
| 額外效益 | 訓練出的小型 drafter 可直接部署用於高效推理 |

「人們希望模型能處理更複雜的任務。但如果這是模型開發的目標，那我們就必須優先解決效率問題。我們找到了一個無損的解決方案，並開發了一個能在實務上實現顯著加速的全棧系統。」Hu 說。

「隨著推理（reasoning）持續成為驅動推理（inference）需求的主要工作負載，Hu 的 TLT 是應對訓練推理模型的計算瓶頸的傑出工作。我認為這個方法在高效 AI 計算的脈絡下會非常有幫助。」資深作者、MIT 副教授兼 NVIDIA 傑出科學家 Song Han 表示。

### 後續發展方向

研究團隊計畫將 TLT 整合至更多種類的訓練與推理框架，並探索其他可被 TLT 加速的強化學習應用。論文已於 arXiv 公開（arXiv:2511.16665），將在 ACM ASPLOS 國際會議發表。

## 💡 觀察與啟發

TLT 的精妙之處在於它解決的是一個被普遍忽視的「系統工程」問題——而非模型架構或演算法層面。整個 AI 社群過去幾年都在追逐模型容量與資料規模，卻很少有人注意到：**RL 訓練的 GPU 利用率其實非常低**，因為大家都在等最長那條 rollout 跑完。

把推測解碼從「推理加速技術」轉化為「訓練加速技術」是觀念上的關鍵躍進。傳統推測解碼之所以無法用於 RL 訓練，是因為 drafter 必須靜態；TLT 反其道而行，**把 drafter 訓練本身嵌入 rollout 的閒置時間裡**，讓「等待」變成「準備」。這是典型的系統設計思維：不是更快地做更多工作，而是讓本來會浪費的時間產生價值。

對企業 AI 工程團隊而言，TLT 的方法論可推廣到任何「同步門檻」造成 GPU 閒置的場景——分散式訓練的梯度同步、評估期間的算力空檔、多模型流水線的協調等等。70-210% 的加速幅度若能轉化為訓練成本下降，將直接影響到開源推理模型（如 DeepSeek、Qwen 系列）的迭代速度。值得注意的是，本論文的合作機構涵蓋 NVIDIA、MIT-IBM Watson AI Lab，預期相關優化會迅速進入主流訓練框架。
