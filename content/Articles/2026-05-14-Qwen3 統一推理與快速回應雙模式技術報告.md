# Qwen3 技術報告：把「深度思考」與「快速回應」統一到單一模型

> [!info] 文章資訊
> - **來源**：[arXiv 2505.09388](https://arxiv.org/abs/2505.09388)
> - **發布日期**：2026-05-14
> - **分類**：技術理論

## 📝 重點摘要

阿里巴巴 Qwen 團隊正式發表 Qwen3 技術報告，涵蓋 8 個公開模型（6 個 dense 從 0.6B 到 32B，2 個 MoE 為 30B-A3B 與 235B-A22B）。最關鍵的設計突破是把「思考模式（thinking mode）」與「非思考模式（non-thinking mode）」整合進同一個統一框架，使用者或對話模板可以動態切換，不再需要在「快速模型」與「推理模型」之間二擇一。架構上沿用 GQA、SwiGLU、RoPE、RMSNorm 等熟悉組件，但移除 QKV-bias、引入 QK-Norm 以穩定大規模訓練；MoE 變體採 128 專家、每 token 啟用 8 個的「fine-grained expert segmentation」，並透過 global-batch load balancing loss 鼓勵專家分化。

## 📖 全文內容

### 模型家族總覽

Qwen3 系列同時提供 dense 與 MoE 兩種架構，參數規模從 0.6B 一直橫跨到 235B，足以對應從邊緣端到資料中心的多種部署情境：

- **Dense 模型**：Qwen3-0.6B、1.7B、4B、8B、14B、32B
- **MoE 模型**：Qwen3-30B-A3B（總參數 30B、每 token 啟用 3B）、Qwen3-235B-A22B（總參數 235B、每 token 啟用 22B）

A 後綴明確標示「activated」參數量，符合 2026 年產業界對 MoE 透明溝通的慣例（與 Google Gemma 4 MoE 26B-A3.8B 同期呼應）。

### Dense 模型架構細節

Qwen3 dense 模型整體與 Qwen2.5 相近，但做了兩個關鍵調整：

- **移除 QKV-bias**：簡化參數量、降低訓練不穩定的風險。
- **新增 QK-Norm**：在注意力的 Query 與 Key 上額外做歸一化，提升大規模訓練時的數值穩定度。

其餘元件包含：

- **Grouped Query Attention（GQA）**：壓縮 KV cache、降低推論記憶體。
- **SwiGLU**：FFN 中的非線性。
- **RoPE**：旋轉位置編碼。
- **RMSNorm + Pre-Norm**：穩定深層 transformer 訓練。

### MoE 架構：細粒度專家分割

Qwen3 MoE 模型與 dense 共用 backbone，但對專家層做兩點重要更動：

1. **128 專家、每 token 啟用 8 個**：相較 Qwen2.5-MoE 的較粗粒度切分，Qwen3 走「fine-grained expert segmentation」路線——專家更多、每個更小，激活組合也更精細。
2. **取消共享專家（shared experts）**：把所有容量都交給可路由專家，並用 **global-batch load balancing loss** 鼓勵專家分化、避免少數專家被過度使用。

### 雙模式統一：thinking / non-thinking 在同一個模型內

Qwen3 最具行銷亮點、也是技術上最有意思的設計——把推理模型典型的 `<think>...</think>` 長鏈思考行為，與一般 chat 模型的快速回應，整合在同一組權重內。使用者可以：

- 透過明確的 chat template 切換到 thinking mode（適合數學、程式、研究等需要多步推理的場景）。
- 在簡單對話下走 non-thinking mode（節省 token、降低延遲）。
- 由 query 內容動態觸發切換（dynamic mode switching）。

這項設計把過去 OpenAI o1 / o3、DeepSeek-R1 系列「另外發一個推理變體」的二元路線改成「模型內建雙人格」，對部署團隊而言代表單一權重檔即可服務兩種使用情境，大幅簡化基礎設施。

## 💡 觀察與啟發

Qwen3 技術報告同時揭示了 2026 年中段的兩個重要趨勢。其一是 **MoE 架構在開源世界的標準化**：細粒度切分（128 專家、激活 8 個）已成新共識，並與 Google Gemma 4 MoE、DeepSeek-V3 系列等指向相同方向——「更多但更小的專家」正在取代「少而大的專家」。其二是 **推理與快速回應的合一**：把 thinking mode 內建到單一模型，對企業導入端是極大利多，不再需要在路由層自己判斷「這個 query 該丟給哪一個模型」，可以把這個 burden 交還給模型本身。對台灣中小企業導入 AI 而言，Qwen3 的 0.6B / 1.7B 小模型 + thinking mode 內建，可能會是低成本部署本地 agent 的最佳選項之一。
